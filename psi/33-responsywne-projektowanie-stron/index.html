Responsywne projektowanie stron – viewport, jednostki elastyczne i media queries

Cel lekcji: poznanie zasad responsywnego projektowania stron internetowych oraz wykorzystanie jednostek elastycznych, właściwości CSS i media queries do dostosowywania układu witryny do różnych szerokości ekranu.

Czas realizacji: 2 × 45 minut.

1. Wprowadzenie

Strony internetowe są wyświetlane na urządzeniach o różnych rozmiarach ekranów: komputerach, laptopach, tabletach i smartfonach.

Strona zaprojektowana wyłącznie dla dużego monitora może być niewygodna podczas przeglądania na telefonie.

Przykładowe problemy

  • Tekst jest zbyt mały i trudny do przeczytania.
  • Menu nie mieści się na ekranie.
  • Obrazy wychodzą poza szerokość strony.
  • Karty są zbyt wąskie.
  • Użytkownik musi przewijać stronę poziomo.
  • Przyciski są zbyt małe lub znajdują się zbyt blisko siebie.

Rozwiązaniem jest responsywne projektowanie stron.

📌 Zapamiętaj

Dobrze zaprojektowana strona powinna być czytelna i wygodna w obsłudze zarówno na dużym, jak i małym ekranie.

2. Czym jest RWD?

RWD (Responsive Web Design) to sposób projektowania stron internetowych, w którym układ i wygląd strony dostosowują się do dostępnej przestrzeni.

Responsywność nie polega wyłącznie na zmniejszeniu całej strony.

Elementy mogą zmieniać:

  • szerokość,
  • wysokość,
  • rozmieszczenie,
  • kierunek ułożenia,
  • odstępy,
  • rozmiary tekstu.

Przykład – trzy karty

Na dużym ekranie: 

+------------+ +------------+ +------------+
|   KARTA 1  | |   KARTA 2  | |   KARTA 3  |
+------------+ +------------+ +------------+

Na małym ekranie: 

+------------------+
|      KARTA 1     |
+------------------+

+------------------+
|      KARTA 2     |
+------------------+

+------------------+
|      KARTA 3     |
+------------------+

Zawartość pozostaje taka sama, ale zmienia się sposób rozmieszczenia elementów.

Podstawowe techniki RWD

  1. Poprawne ustawienie viewport.
  2. Stosowanie elastycznych rozmiarów.
  3. Ograniczanie maksymalnej szerokości elementów.
  4. Tworzenie elastycznych układów Flexbox.
  5. Wykorzystanie media queries.
  6. Dostosowywanie obrazów i tekstu.

3. Meta viewport

Viewport to obszar przeglądarki, w którym wyświetlana jest strona internetowa.

W responsywnym dokumencie HTML należy umieścić znacznik: 

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

Znacznik umieszczamy wewnątrz sekcji head.

Znaczenie atrybutów

Fragment Znaczenie
name="viewport" Określa ustawienia obszaru wyświetlania strony.
width=device-width Ustawia szerokość viewport zgodnie z szerokością urządzenia w pikselach CSS.
initial-scale=1.0 Ustawia początkową skalę strony na 1.

Przykład poprawnego dokumentu

<!DOCTYPE html>
<html lang="pl">

<head>

    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Responsywna strona</title>

    <link rel="stylesheet" href="style.css">

</head>

<body>

    <h1>Moja responsywna strona</h1>

</body>

</html>

📌 Zapamiętaj

Znacznik viewport nie tworzy samodzielnie responsywnego układu, ale pozwala przeglądarkom mobilnym prawidłowo interpretować szerokość strony.

4. Mobile First i Desktop First

Podczas projektowania responsywnych stron można stosować dwa podejścia.

Mobile First

Najpierw przygotowujemy wygląd strony dla małych ekranów, a następnie rozszerzamy układ dla większych. 

/* Wygląd podstawowy – małe ekrany */

.karty {
    display: flex;
    flex-direction: column;
}

/* Większe ekrany */

@media (min-width: 768px) {

    .karty {
        flex-direction: row;
    }

}

Desktop First

Najpierw przygotowujemy układ dla większych ekranów, a później dostosowujemy go do mniejszych. 

/* Wygląd podstawowy – większe ekrany */

.karty {
    display: flex;
    flex-direction: row;
}

/* Małe ekrany */

@media (max-width: 767px) {

    .karty {
        flex-direction: column;
    }

}

Porównanie

Mobile First Desktop First
Projektowanie zaczyna się od małego ekranu. Projektowanie zaczyna się od dużego ekranu.
Często stosuje się min-width. Często stosuje się max-width.
Rozbudowujemy układ wraz ze wzrostem szerokości. Upraszczamy układ wraz ze zmniejszaniem szerokości.

📌 Zapamiętaj

Oba podejścia są poprawne. W jednym projekcie warto zachować spójny sposób organizowania reguł CSS.

5. Jednostki CSS a responsywność

W CSS możemy stosować jednostki bezwzględne i względne.

Jednostki względne często ułatwiają tworzenie elastycznych układów.

Jednostka Znaczenie Przykład
px Piksele CSS. padding: 20px
% Procent wartości odniesienia zależnej od właściwości. width: 80%
em Jednostka zależna od rozmiaru czcionki. padding: 2em
rem Jednostka zależna od rozmiaru czcionki elementu głównego. font-size: 1.5rem
vw Procent szerokości viewport. width: 80vw
vh Procent wysokości viewport. min-height: 100vh
dvh Procent dynamicznej wysokości viewport. min-height: 100dvh

Nie oznacza to, że jednostka px jest niepoprawna.

W responsywnych projektach często łączy się różne jednostki.

6. Jednostka procentowa – %

Procenty pozwalają określać rozmiary w odniesieniu do innej wartości.

Przykład

.kontener {
    width: 80%;
}

W typowym układzie blokowym oznacza to szerokość równą 80% szerokości bloku zawierającego.

Przykład dwóch kolumn

.uklad {
    display: flex;
}

.lewy {
    width: 60%;
}

.prawy {
    width: 40%;
}

Kolumny zajmują odpowiednio 60% i 40% dostępnej szerokości.

Ważne

Znaczenie procentów zależy od właściwości CSS. Na przykład procentowe szerokości i wysokości mogą mieć różne zasady obliczania.

📌 Dobra praktyka

Dla głównego kontenera strony można połączyć szerokość procentową z ograniczeniem maksymalnej szerokości. 

.kontener {
    width: 90%;
    max-width: 1200px;

    margin: 0 auto;
}

7. Jednostki em i rem

Jednostki em i rem są powiązane z rozmiarem czcionki.

Jednostka rem

1rem odpowiada rozmiarowi czcionki elementu głównego html. 

html {
    font-size: 16px;
}

h1 {
    font-size: 2rem;
}

p {
    font-size: 1rem;
}

Przy takim ustawieniu:

  • 1rem = 16px,
  • 2rem = 32px.

Jednostka em

Przy właściwości font-size jednostka em odnosi się do rozmiaru czcionki rodzica.

W przypadku wielu innych właściwości, np. padding, odnosi się do rozmiaru czcionki samego elementu. 

.karta {
    font-size: 20px;

    padding: 1.5em;
}

W tym przypadku padding wyniesie 30 px.

Porównanie

Jednostka Od czego zależy?
rem Od rozmiaru czcionki elementu html.
em Od kontekstu rozmiaru czcionki danego elementu.

📌 Zapamiętaj

rem jest wygodne do ustalania spójnych rozmiarów tekstu i odstępów na całej stronie.

8. Jednostki vw, vh i dvh

Jednostki viewport pozwalają określać rozmiary w odniesieniu do obszaru wyświetlania strony.

vw – szerokość viewport

.baner {
    width: 80vw;
}

80vw odpowiada 80% szerokości viewport.

vh – wysokość viewport

.baner {
    min-height: 70vh;
}

Minimalna wysokość banera odpowiada 70% wysokości viewport.

dvh – dynamiczna wysokość viewport

.baner {
    min-height: 100dvh;
}

Jednostka dvh uwzględnia dynamiczne zmiany dostępnej wysokości viewport, np. związane z paskami przeglądarki mobilnej.

Przykład

.powitanie {
    min-height: 60vh;

    display: flex;

    justify-content: center;
    align-items: center;

    text-align: center;
}

Zawartość sekcji będzie wyśrodkowana, a wysokość sekcji będzie zależeć od wysokości viewport.

📌 Uwaga

Stosowanie 100vw dla elementów strony nie zawsze jest potrzebne i może powodować poziome przewijanie, np. gdy szerokość obejmuje obszar paska przewijania.

9. Ograniczanie rozmiarów – min-width i max-width

Właściwości min-width i max-width określają minimalną i maksymalną szerokość elementu.

max-width

.kontener {
    width: 90%;
    max-width: 1100px;
}

Kontener może zajmować 90% dostępnej szerokości, ale nie będzie szerszy niż 1100 px.

min-width

.przycisk {
    min-width: 150px;
}

Element nie będzie węższy niż 150 px, o ile nie zostanie to zmienione przez inne reguły układu.

Praktyczny kontener strony

.kontener {
    width: 90%;

    max-width: 1200px;

    margin: 0 auto;
}

To popularny sposób tworzenia głównego obszaru zawartości strony.

📌 Dobra praktyka

Zbyt duże wartości min-width mogą powodować, że element nie zmieści się na ekranie telefonu.

10. Funkcje calc(), min(), max() i clamp()

CSS udostępnia funkcje, które umożliwiają elastyczne obliczanie rozmiarów elementów.

calc()

Funkcja calc() pozwala wykonywać obliczenia na wartościach CSS. 

.kontener {
    width: calc(100% - 40px);
}

Szerokość elementu będzie równa dostępnej szerokości pomniejszonej o 40 px.

min()

.kontener {
    width: min(90%, 1100px);
}

Przeglądarka wybierze mniejszą z podanych wartości.

max()

.kontener {
    padding: max(15px, 2vw);
}

Przeglądarka wybierze większą z podanych wartości.

clamp()

Funkcja clamp() określa wartość minimalną, preferowaną i maksymalną. 

h1 {
    font-size: clamp(24px, 4vw, 48px);
}

Rozmiar tekstu:

  • nie będzie mniejszy niż 24 px,
  • będzie dostosowywany według 4vw,
  • nie będzie większy niż 48 px.

📌 Zapamiętaj

clamp() pozwala uzyskać płynne zmiany rozmiaru bez konieczności tworzenia wielu reguł @media.

11. Responsywne obrazy

Obrazy o stałej, dużej szerokości mogą wychodzić poza ekran telefonu.

Przykład problemu

img {
    width: 1000px;
}

Na ekranie węższym niż 1000 px taki obraz może powodować poziome przewijanie.

Poprawne rozwiązanie

img {
    max-width: 100%;
    height: auto;
}

max-width: 100% ogranicza szerokość obrazu do dostępnej szerokości jego kontenera.

height: auto pozwala zachować proporcje obrazu.

Przykład HTML

<img src="img/komputer.jpg"
     alt="Stanowisko komputerowe">

Obraz wypełniający kontener

.zdjecie {
    width: 100%;
    height: 250px;

    object-fit: cover;
}

Właściwość object-fit: cover powoduje wypełnienie wyznaczonego obszaru, ale część obrazu może zostać przycięta.

📌 Zapamiętaj

Do podstawowego dostosowywania obrazów bardzo często wystarcza: 

img {
    max-width: 100%;
    height: auto;
}

12. Media queries – reguła @media

Media queries umożliwiają stosowanie różnych reguł CSS w zależności od warunków, np. szerokości viewport.

Podstawowa składnia

@media (warunek) {

    selektor {
        właściwość: wartość;
    }

}

Przykład – zmiana koloru tła

body {
    background-color: white;
}

@media (max-width: 600px) {

    body {
        background-color: #DBEAFE;
    }

}

Gdy szerokość viewport wynosi maksymalnie 600 px, tło strony zmieni kolor.

min-width

@media (min-width: 768px) {

    .karty {
        flex-direction: row;
    }

}

Reguła działa przy szerokości viewport wynoszącej co najmniej 768 px.

max-width

@media (max-width: 767px) {

    .karty {
        flex-direction: column;
    }

}

Reguła działa przy szerokości viewport wynoszącej maksymalnie 767 px.

Łączenie warunków

@media (min-width: 600px) and (max-width: 1000px) {

    .kontener {
        width: 85%;
    }

}

Powyższe reguły będą obowiązywały w podanym przedziale szerokości viewport.

Media queries a kaskadowość

Reguły znajdujące się wewnątrz @media podlegają tym samym zasadom kaskadowości i specyficzności co pozostałe reguły CSS.

📌 Zapamiętaj

@media nie tworzy nowej strony. Zmienia jedynie sposób formatowania tej samej zawartości.

13. Punkty przełamania – breakpoints

Breakpoint to wartość graniczna, przy której zmienia się układ lub wygląd strony.

Przykładowe wartości

Szerokość Przykładowe zastosowanie
Do 600 px Zmiana menu poziomego na pionowe.
Do 768 px Ustawienie dwóch kolumn jedna pod drugą.
Od 1024 px Rozbudowany układ dla szerszego ekranu.

Są to wartości przykładowe. Nie istnieje jeden obowiązkowy zestaw breakpointów dla wszystkich stron.

Przykład

.karty {
    display: flex;
    flex-direction: column;
}

@media (min-width: 700px) {

    .karty {
        flex-direction: row;
    }

}

Przy szerokości mniejszej niż 700 px karty będą ustawione w kolumnie.

Przy szerokości co najmniej 700 px będą ustawione w wierszu.

📌 Dobra praktyka

Punkt przełamania warto dobrać do momentu, w którym układ strony zaczyna wyglądać źle, zamiast kierować się wyłącznie nazwą urządzenia.

14. Responsywne menu nawigacyjne

Na dużym ekranie menu może być poziome, a na telefonie pionowe.

HTML

<nav class="menu">

    <a href="#start">Start</a>

    <a href="#oferta">Oferta</a>

    <a href="#galeria">Galeria</a>

    <a href="#kontakt">Kontakt</a>

</nav>

CSS – duży ekran

.menu {
    display: flex;

    justify-content: center;

    gap: 20px;

    padding: 15px;

    background-color: #1E3A8A;
}

.menu a {
    padding: 10px 15px;

    color: white;
    text-decoration: none;
}

CSS – mały ekran

@media (max-width: 600px) {

    .menu {
        flex-direction: column;

        align-items: stretch;

        gap: 10px;
    }

    .menu a {
        text-align: center;
    }

}

Efekt

Na dużym ekranie: 

Start    Oferta    Galeria    Kontakt

Na małym ekranie: 

Start

Oferta

Galeria

Kontakt

📌 Zapamiętaj

Responsywne menu można wykonać za pomocą samego HTML i CSS. Nie zawsze potrzebny jest JavaScript.

15. Responsywny układ kart za pomocą Flexbox

Flexbox pozwala tworzyć układy, które dostosowują się do dostępnej szerokości.

HTML

<div class="karty">

    <article class="karta">
        <h3>HTML</h3>
        <p>Struktura strony.</p>
    </article>

    <article class="karta">
        <h3>CSS</h3>
        <p>Wygląd strony.</p>
    </article>

    <article class="karta">
        <h3>JavaScript</h3>
        <p>Interaktywność.</p>
    </article>

</div>

CSS

.karty {
    display: flex;

    flex-wrap: wrap;

    gap: 20px;
}

.karta {
    flex: 1 1 250px;

    min-width: 0;

    padding: 20px;

    background-color: #DBEAFE;

    border-radius: 10px;
}

Karty będą próbowały zajmować dostępną przestrzeń w wierszu.

Jeśli zabraknie miejsca, zostaną przeniesione do kolejnego wiersza.

Wariant Mobile First

.karty {
    display: flex;

    flex-direction: column;

    gap: 20px;
}

@media (min-width: 768px) {

    .karty {
        flex-direction: row;
    }

    .karta {
        flex: 1;
    }

}

Na małych ekranach karty są ustawione jedna pod drugą.

Na większych ekranach znajdują się obok siebie.

16. Responsywna typografia

Rozmiary tekstu powinny zapewniać czytelność na różnych szerokościach ekranu.

Zmiana rozmiaru przez @media

h1 {
    font-size: 40px;
}

@media (max-width: 600px) {

    h1 {
        font-size: 26px;
    }

}

Na małym ekranie nagłówek będzie mniejszy.

Płynna typografia z clamp()

h1 {
    font-size: clamp(26px, 4vw, 48px);
}

Rozmiar nagłówka będzie dostosowywał się płynnie do szerokości viewport, w podanych granicach.

Przykład akapitu

p {
    font-size: 1rem;

    line-height: 1.6;
}

Odpowiednia wysokość linii poprawia czytelność tekstu.

📌 Dobra praktyka

Nie zmniejszaj nadmiernie tekstu tylko po to, aby zmieścić więcej treści na małym ekranie.

17. Testowanie responsywności strony

Responsywność należy sprawdzać podczas pracy, a nie dopiero po zakończeniu projektu.

Sposób 1 – zmiana szerokości okna

  1. Otwórz stronę w przeglądarce.
  2. Zmniejsz szerokość okna.
  3. Obserwuj zmiany układu.
  4. Sprawdź menu, obrazy, karty i tekst.

Sposób 2 – narzędzia deweloperskie

  1. Otwórz stronę w Chrome lub Edge.
  2. Naciśnij klawisz F12.
  3. Włącz tryb urządzenia mobilnego – ikonę telefonu i tabletu.
  4. Wybierz przykładową szerokość ekranu.
  5. Sprawdź wygląd strony.
  6. Zmieniaj szerokość viewport i obserwuj układ.

Przykładowe szerokości testowe

Szerokość viewport Cel testu
360 px Wąski ekran telefonu.
390 px Typowa szerokość mobilna.
768 px Węższy ekran tabletu lub okno przeglądarki.
1024 px Szerszy tablet lub małe okno desktopowe.
1440 px Duży ekran komputera.

Podane szerokości są przykładowymi wartościami do testów, a nie sztywnymi kategoriami urządzeń.

Lista kontrolna

  • Czy tekst jest czytelny?
  • Czy menu mieści się na ekranie?
  • Czy obrazy zachowują proporcje?
  • Czy karty poprawnie zmieniają układ?
  • Czy przyciski można wygodnie nacisnąć?
  • Czy nie pojawia się niepotrzebne przewijanie poziome?
  • Czy wszystkie sekcje są dostępne?

18. Najczęstsze błędy

Błąd 1 – brak meta viewport

Na telefonie strona może być wyświetlana w nieodpowiedniej skali.

Rozwiązanie:

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

Błąd 2 – sztywna szerokość strony

.kontener {
    width: 1200px;
}

Na małym ekranie kontener może wychodzić poza viewport.

Lepsze rozwiązanie:

.kontener {
    width: 90%;
    max-width: 1200px;
}

Błąd 3 – zbyt duży obraz

img {
    width: 900px;
}

Lepsze rozwiązanie:

img {
    max-width: 100%;
    height: auto;
}

Błąd 4 – brak zmiany kierunku menu

Menu poziome może nie mieścić się na małym ekranie. 

@media (max-width: 600px) {

    .menu {
        flex-direction: column;
    }

}

Błąd 5 – błędny zapis @media

@media max-width: 600px {
    /* Błędna składnia */
}

Poprawnie:

@media (max-width: 600px) {

    .menu {
        flex-direction: column;
    }

}

Błąd 6 – niepotrzebne używanie 100vw

W niektórych układach width: 100vw może spowodować poziome przewijanie.

Dla elementu blokowego często wystarczy jego domyślna automatyczna szerokość.

Błąd 7 – brak testów

Strona może wyglądać poprawnie na komputerze, ale mieć problemy na telefonie.

📌 Zapamiętaj

Responsywność należy sprawdzać na różnych szerokościach, również pomiędzy wybranymi breakpointami.

19. Kompletny przykład – responsywna strona „Technologie WWW”

Poniższy przykład przedstawia stronę internetową, która dostosowuje układ do szerokości viewport.

Wykorzystamy:

  • meta viewport,
  • jednostki procentowe i rem,
  • max-width,
  • clamp(),
  • Flexbox,
  • media queries,

Oczekiwany efekt

  1. Na dużym ekranie menu jest poziome.
  2. Na małym ekranie menu jest pionowe.
  3. Karty dostosowują się do dostępnej szerokości.
  4. Na wąskim ekranie karty znajdują się jedna pod drugą.
  5. Nagłówki mają elastyczne rozmiary.
  6. Główny kontener nie przekracza 1100 px szerokości.
  7. Strona nie wymaga poziomego przewijania przy typowych szerokościach ekranu.

📌 Zapamiętaj

  • RWD oznacza Responsive Web Design.
  • Responsywna strona dostosowuje układ do dostępnej przestrzeni.
  • Viewport to obszar wyświetlania strony.
  • Znacznik meta viewport należy umieścić w sekcji head.
  • width=device-width ustawia szerokość viewport zgodnie z szerokością urządzenia w pikselach CSS.
  • initial-scale=1.0 ustawia początkową skalę.
  • Mobile First oznacza projektowanie najpierw dla małych ekranów.
  • Desktop First oznacza projektowanie najpierw dla dużych ekranów.
  • Jednostka % pozwala określać wartości względne.
  • Jednostka rem zależy od rozmiaru czcionki elementu html.
  • Jednostka em zależy od kontekstu rozmiaru czcionki.
  • Jednostka vw odnosi się do szerokości viewport.
  • Jednostka vh odnosi się do wysokości viewport.
  • Jednostka dvh uwzględnia dynamiczną wysokość viewport.
  • max-width ogranicza maksymalną szerokość elementu.
  • min-width określa minimalną szerokość elementu.
  • calc() pozwala wykonywać obliczenia w CSS.
  • min() wybiera mniejszą z wartości.
  • max() wybiera większą z wartości.
  • clamp() określa minimum, wartość preferowaną i maksimum.
  • max-width: 100% pomaga dostosować obrazy do kontenera.
  • height: auto pozwala zachować proporcje obrazu.
  • @media umożliwia zmianę stylów zależnie od warunków.
  • min-width w media queries określa dolną granicę szerokości.
  • max-width w media queries określa górną granicę szerokości.
  • Breakpoint to punkt, w którym zmienia się układ strony.
  • Flexbox ułatwia tworzenie responsywnych kart i menu.
  • Responsywność należy testować na różnych szerokościach viewport.

📝 Zadania praktyczne

Cel: wykonanie responsywnej strony internetowej z wykorzystaniem viewport, jednostek elastycznych, Flexbox i media queries.

Utwórz folder PSI_33, a w nim pliki index.html i style.css.

Wszystkie zadania wykonaj w ramach jednego projektu. Każde kolejne zadanie rozbudowuje tę samą stronę.

Zadanie 1 – Struktura responsywnej strony

Przygotuj stronę „Moje zainteresowania” lub „Moja oferta”.

  1. Utwórz poprawny dokument HTML5.
  2. Ustaw język dokumentu na polski.
  3. Dodaj kodowanie UTF-8.
  4. Dodaj znacznik meta viewport.
  5. Podłącz zewnętrzny arkusz style.css.
  6. Dodaj nagłówek strony z własnym tytułem.
  7. Dodaj menu z co najmniej trzema odnośnikami.
  8. Dodaj sekcję powitalną.
  9. Dodaj sekcję z co najmniej trzema kartami.
  10. Dodaj stopkę z imieniem i nazwiskiem autora.

Zadanie 2 – Elastyczne rozmiary elementów

Dostosuj szerokości i odstępy na stronie.

  1. Ustaw dla całej strony margin: 0.
  2. Zastosuj box-sizing: border-box.
  3. Utwórz klasę kontener.
  4. Ustaw szerokość kontenera na 90%.
  5. Ustaw maksymalną szerokość na 1100 px.
  6. Wyśrodkuj kontener za pomocą margin: 0 auto.
  7. Wykorzystaj jednostki rem do ustawienia paddingu.
  8. Ustaw odstępy między sekcjami.

Zadanie 3 – Responsywne menu i karty

Zastosuj Flexbox do rozmieszczenia elementów strony.

  1. Ustaw display: flex dla menu.
  2. Wyśrodkuj odnośniki.
  3. Dodaj odstępy między odnośnikami za pomocą gap.
  4. Ustaw display: flex dla kontenera kart.
  5. Dodaj flex-wrap: wrap.
  6. Ustaw dla kart flex: 1 1 250px.
  7. Dodaj odstępy między kartami.
  8. Zmniejsz szerokość okna przeglądarki i obserwuj układ.

Zadanie 4 – Responsywne obrazy i tekst

Rozbuduj stronę o elementy graficzne i elastyczną typografię.

  1. Dodaj co najmniej jeden obraz do strony.
  2. Umieść obraz w katalogu img.
  3. Ustaw dla obrazu max-width: 100%.
  4. Ustaw height: auto.
  5. Dodaj odpowiedni atrybut alt.
  6. Ustaw rozmiar głównego nagłówka za pomocą clamp().
  7. Zastosuj jednostki rem dla tekstu i odstępów.
  8. Sprawdź wygląd obrazu i tekstu na małym ekranie.

Zadanie 5 – Media queries

Dostosuj układ strony do szerokości viewport.

  1. Dodaj regułę @media (max-width: 600px).
  2. Na małym ekranie ustaw menu pionowo.
  3. Wyśrodkuj odnośniki menu.
  4. Ustaw karty jedna pod drugą.
  5. Zmniejsz padding sekcji powitalnej.
  6. Dodaj regułę dla szerokości od 601 px do 900 px.
  7. W tym przedziale ustaw szerokość głównego kontenera na 92%.
  8. Sprawdź, czy wszystkie reguły działają poprawnie.

Zadanie 6 – Testowanie responsywności

Sprawdź gotową stronę w narzędziach deweloperskich przeglądarki.

  1. Uruchom stronę w Chrome lub Edge.
  2. Otwórz narzędzia deweloperskie klawiszem F12.
  3. Włącz widok urządzenia mobilnego.
  4. Sprawdź stronę przy szerokości 360 px.
  5. Sprawdź stronę przy szerokości 768 px.
  6. Sprawdź stronę przy szerokości 1024 px.
  7. Sprawdź stronę przy szerokości 1440 px.
  8. Upewnij się, że nie występuje niepotrzebne przewijanie poziome.
  9. Sprawdź, czy menu i karty zmieniają układ.
  10. Popraw zauważone błędy.
