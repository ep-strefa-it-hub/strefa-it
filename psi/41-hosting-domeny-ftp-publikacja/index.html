PSI • LEKCJA 41 • HOSTING I PUBLIKOWANIE

Hosting, domeny, FTP oraz publikowanie i sprawdzanie witryny na serwerze WWW

Cel lekcji: poznanie zasad działania hostingu, domen internetowych i systemu DNS, sposobów przesyłania plików na serwer oraz samodzielne opublikowanie i przetestowanie statycznej witryny internetowej.

Czas realizacji: 2 × 45 minut.

1. Wprowadzenie

Podczas wcześniejszych lekcji tworzyliśmy strony internetowe za pomocą HTML i CSS, testowaliśmy je w przeglądarkach oraz poprawialiśmy ich wydajność.

Dotychczas pliki znajdowały się przede wszystkim na komputerze autora.

Aby witryna była dostępna dla innych użytkowników internetu, należy opublikować ją na odpowiednio skonfigurowanym serwerze WWW.

Co jest potrzebne do publikacji?

  • Gotowe pliki strony internetowej.
  • Miejsce do przechowywania i udostępniania plików.
  • Adres umożliwiający otwarcie strony.
  • Metoda przesłania plików na serwer.
  • Możliwość sprawdzenia działania opublikowanej witryny.

📌 Zapamiętaj

Publikacja witryny oznacza udostępnienie jej w taki sposób, aby użytkownicy mogli otworzyć ją przez internet.

2. Czym jest serwer WWW?

Serwer WWW to system udostępniający zasoby stron internetowych za pomocą protokołów HTTP lub HTTPS.

Określenie „serwer” może oznaczać zarówno komputer, jak i oprogramowanie obsługujące żądania.

Jak działa otwieranie strony?

  1. Użytkownik wpisuje adres witryny w przeglądarce.
  2. Przeglądarka ustala, z jakim serwerem należy się połączyć.
  3. Wysyła żądanie HTTP lub HTTPS.
  4. Serwer zwraca odpowiedź i odpowiednie zasoby.
  5. Przeglądarka interpretuje HTML, CSS i JavaScript.
  6. Użytkownik widzi gotową stronę.

Przykładowe oprogramowanie serwerowe

  • Apache HTTP Server.
  • Nginx.
  • Microsoft IIS.

Na wcześniejszych lekcjach korzystaliśmy z XAMPP, który umożliwia uruchomienie lokalnego serwera Apache.

Serwer lokalny służy przede wszystkim do pracy i testowania, natomiast publiczny serwer WWW udostępnia stronę innym użytkownikom.

3. Czym jest hosting internetowy?

Hosting to usługa udostępniania zasobów potrzebnych do przechowywania i obsługi witryny internetowej.

Firma świadcząca hosting udostępnia odpowiednią infrastrukturę, dzięki której witryna może działać w internecie.

Co może oferować hosting?

  • Miejsce na pliki strony.
  • Obsługę serwera WWW.
  • Dostęp przez SFTP lub FTPS.
  • Bazy danych.
  • Obsługę PHP.
  • Certyfikaty TLS dla HTTPS.
  • Kopie bezpieczeństwa.
  • Panele administracyjne.

Zakres dostępnych funkcji zależy od wybranego dostawcy i rodzaju usługi.

Przykład

Szkoła chce opublikować witrynę informacyjną. Może skorzystać z hostingu, na którym zostaną umieszczone pliki HTML, CSS i obrazy.

Jeżeli witryna korzysta z PHP i MySQL, hosting musi dodatkowo obsługiwać odpowiednie technologie serwerowe.

4. Rodzaje hostingu

Dostępne są różne sposoby udostępniania witryn internetowych.

Rodzaj Charakterystyka Przykładowe zastosowanie
Hosting współdzielony Wiele witryn korzysta ze wspólnej infrastruktury serwera. Małe strony firmowe, blogi.
VPS Wirtualny serwer z wydzielonym środowiskiem. Bardziej rozbudowane projekty.
Serwer dedykowany Serwer przeznaczony dla jednego klienta. Duże systemy wymagające większej kontroli.
Hosting statyczny Udostępnia gotowe pliki HTML, CSS i JavaScript. Portfolio, wizytówki, strony projektowe.

Hosting statyczny

Jest szczególnie przydatny podczas nauki HTML i CSS.

Przykładem takiej usługi jest GitHub Pages.

⚠️ Ważne

GitHub Pages nie uruchamia kodu PHP ani serwera MySQL.

Nadaje się do publikowania statycznych stron HTML, CSS i JavaScript, ale nie do bezpośredniego uruchamiania aplikacji PHP.

5. Domeny internetowe

Domena internetowa to nazwa wykorzystywana do identyfikowania zasobów i usług w internecie.

Dzięki domenom nie musimy zapamiętywać adresów IP serwerów.

Przykład domeny

example.com

Elementy nazwy

Element Przykład
Nazwa domeny drugiego poziomu example
Domena najwyższego poziomu (TLD) .com
Subdomena blog.example.com

Przykładowe rozszerzenia

  • .pl – domena krajowa Polski.
  • .com – domena ogólna.
  • .org – domena ogólna.
  • .edu.pl – przestrzeń nazw używana m.in. przez podmioty edukacyjne.

Domena a hosting

Domena jest nazwą, natomiast hosting zapewnia infrastrukturę potrzebną do udostępniania witryny.

Są to powiązane, ale odrębne usługi.

6. System DNS

DNS to skrót od Domain Name System.

System DNS pomaga odnaleźć informacje potrzebne do połączenia z usługą wskazaną nazwą domenową.

Przykład

www.example.com

Przeglądarka może wykorzystać DNS, aby uzyskać adres IP serwera obsługującego wskazaną nazwę.

Popularne rekordy DNS

Rekord Zastosowanie
A Powiązanie nazwy z adresem IPv4.
AAAA Powiązanie nazwy z adresem IPv6.
CNAME Wskazanie innej nazwy domenowej.
MX Wskazanie serwerów obsługujących pocztę.
TXT Przechowywanie informacji tekstowych, np. do weryfikacji usług.

📌 Zapamiętaj

DNS umożliwia korzystanie z nazw domenowych zamiast bezpośredniego wpisywania adresów IP.

7. Adres URL oraz HTTP i HTTPS

URL określa adres zasobu dostępnego w internecie.

Przykład

https://example.com/kursy/html.html
Fragment Znaczenie
https:// Schemat określający sposób dostępu.
example.com Nazwa hosta.
/kursy/html.html Ścieżka do zasobu.

HTTP a HTTPS

HTTP służy do komunikacji między klientem a serwerem WWW.

HTTPS wykorzystuje zabezpieczenie TLS, dzięki któremu połączenie jest szyfrowane i może być uwierzytelnione.

⚠️ Ważne

HTTPS zabezpiecza połączenie, ale samo w sobie nie gwarantuje, że treść witryny jest wiarygodna lub że właściciel strony nie próbuje oszukać użytkownika.

8. Protokół FTP

FTP to skrót od File Transfer Protocol.

Protokół ten służy do przesyłania plików między komputerem klienta a serwerem.

Do czego wykorzystywano FTP?

  • Przesyłania plików HTML.
  • Przesyłania arkuszy CSS.
  • Wgrywania obrazów.
  • Aktualizowania zawartości witryny.
  • Pobierania plików z serwera.

Podstawowe dane połączenia

Dane Przykład
Host ftp.example.com
Użytkownik konto_testowe
Hasło Hasło przypisane do konta.
Port 21 dla typowego połączenia FTP.

⚠️ Bezpieczeństwo

Zwykły FTP nie zapewnia szyfrowania przesyłanych danych logowania i zawartości.

Do rzeczywistego przesyłania plików należy preferować SFTP lub FTPS.

9. FTP, FTPS i SFTP – różnice

Nazwy tych protokołów są podobne, ale nie oznaczają tego samego rozwiązania.

Protokół Szyfrowanie Charakterystyka
FTP Brak w standardowym FTP. Tradycyjny protokół przesyłania plików.
FTPS TLS. FTP zabezpieczony protokołem TLS.
SFTP SSH. Protokół przesyłania plików działający przez SSH.

Typowe porty

  • FTP – port 21 dla połączenia sterującego.
  • FTPS jawny – zwykle port 21.
  • FTPS niejawny – zwykle port 990.
  • SFTP – zwykle port 22.

Numery portów mogą być inne, jeśli administrator serwera skonfiguruje usługę inaczej.

📌 Zapamiętaj

SFTP nie jest odmianą FTP z dodanym szyfrowaniem. Jest osobnym protokołem działającym przez SSH.

10. Program FileZilla

FileZilla Client to program umożliwiający zarządzanie plikami na serwerze przez obsługiwane protokoły, m.in. FTP, FTPS i SFTP.

Oficjalna strona: filezilla-project.org

Główne obszary programu

  • Panel plików lokalnych.
  • Panel plików zdalnych.
  • Pasek połączenia.
  • Lista przesyłanych plików.
  • Komunikaty o połączeniu i błędach.

Jak wygląda przesyłanie plików?

  1. Uruchom FileZilla Client.
  2. Otwórz Menedżera stron.
  3. Wybierz odpowiedni protokół, najlepiej SFTP lub FTPS.
  4. Wpisz host i port otrzymane od administratora.
  5. Wybierz odpowiednią metodę logowania.
  6. Połącz się z serwerem.
  7. W panelu lokalnym odszukaj folder witryny.
  8. W panelu zdalnym otwórz katalog przeznaczony na pliki strony.
  9. Prześlij odpowiednie pliki i foldery.
  10. Sprawdź, czy transfer zakończył się poprawnie.

⚠️ Ważne

Dane dostępowe do serwera należy przechowywać bezpiecznie. Nie wolno umieszczać haseł w kodzie HTML ani przesyłać ich razem z projektem do Teams.

11. Struktura plików na serwerze WWW

Na wielu hostingach istnieje specjalny katalog, z którego serwer udostępnia pliki witryny.

Jego nazwa zależy od konfiguracji hostingu.

Przykładowe nazwy

  • public_html
  • www
  • htdocs

Przykładowa struktura

public_html/
|
|-- index.html
|
|-- style.css
|
|-- img/
|   |-- logo.png
|   |-- pracownia.jpg
|
|-- js/
    |-- script.js

Dlaczego index.html jest ważny?

W wielu konfiguracjach serwera plik index.html jest traktowany jako domyślny dokument katalogu.

Dzięki temu użytkownik może otworzyć: 

https://example.com/

zamiast wpisywać: 

https://example.com/index.html

📌 Zapamiętaj

Przesyłając stronę na serwer, należy zachować właściwą strukturę katalogów i ścieżki do zasobów.

12. Przesyłanie plików na serwer

Przed publikacją warto sprawdzić, czy folder witryny zawiera wszystkie potrzebne pliki.

Przykładowy folder lokalny

moja-strona/
|
|-- index.html
|-- style.css
|
|-- img/
    |-- logo.png

Publikacja na tradycyjnym hostingu

  1. Połącz się z serwerem przez SFTP lub FTPS.
  2. Otwórz właściwy katalog publikacji.
  3. Prześlij plik index.html.
  4. Prześlij plik style.css.
  5. Prześlij folder img.
  6. Sprawdź, czy wszystkie transfery zakończyły się powodzeniem.
  7. Otwórz publiczny adres witryny.

Przykład ścieżki względnej

<link rel="stylesheet" href="style.css">

<img src="img/logo.png"
     alt="Logo strony">

Jeśli zachowamy strukturę plików, ścieżki względne powinny nadal wskazywać odpowiednie zasoby.

⚠️ Uwaga

Nie należy bez sprawdzenia przesyłać całego folderu projektu jako dodatkowego katalogu, jeśli plik index.html ma znajdować się bezpośrednio w katalogu publikacji.

13. Proces publikowania witryny

Publikacja strony powinna przebiegać według ustalonego planu.

Etap 1 – Przygotowanie

  • Sprawdzenie poprawności HTML i CSS.
  • Sprawdzenie ścieżek do plików.
  • Optymalizacja obrazów.
  • Usunięcie niepotrzebnych plików.

Etap 2 – Wybór usługi

  • Hosting tradycyjny.
  • Hosting statyczny.
  • Inna usługa dostosowana do projektu.

Etap 3 – Przesłanie plików

Pliki można przesłać odpowiednim klientem albo wykorzystać system publikacji oferowany przez dostawcę usługi.

Etap 4 – Testowanie

  • Otwarcie publicznego adresu.
  • Sprawdzenie stylów.
  • Sprawdzenie obrazów.
  • Sprawdzenie odnośników.
  • Sprawdzenie wyglądu na telefonie.

14. GitHub Pages – publikacja statycznej witryny

GitHub Pages umożliwia publikowanie statycznych stron bez konieczności wykupywania tradycyjnego hostingu.

Oficjalna dokumentacja: GitHub Pages

Co można opublikować?

  • Strony HTML.
  • Arkusze CSS.
  • Pliki JavaScript.
  • Obrazy i inne statyczne zasoby.

Przykładowy adres

https://nazwa-uzytkownika.github.io/moj-projekt/

Zalety dla uczniów

  • Możliwość publikowania projektów szkolnych.
  • Brak konieczności kupowania domeny.
  • Możliwość aktualizowania plików przez GitHub.
  • Publiczny adres do zaprezentowania projektu.
  • Obsługa HTTPS dla standardowego adresu GitHub Pages.

⚠️ Ważne

GitHub Pages nie korzysta z FTP ani SFTP jako standardowej metody publikowania projektu.

Pliki publikuje się przez repozytorium GitHub i odpowiednią konfigurację Pages.

15. Publikowanie strony na GitHub Pages – krok po kroku

W tym ćwiczeniu opublikujemy prostą witrynę HTML i CSS.

Krok 1 – Przygotuj pliki

moja-witryna/
|
|-- index.html
|-- style.css
|
|-- img/
    |-- logo.png

Krok 2 – Utwórz repozytorium

  1. Zaloguj się na GitHub.
  2. Wybierz utworzenie nowego repozytorium.
  3. Wpisz nazwę, np. moja-witryna.
  4. Ustaw repozytorium jako publiczne.
  5. Utwórz repozytorium.

Krok 3 – Prześlij pliki

  1. Otwórz repozytorium.
  2. Wybierz Add file → Upload files.
  3. Prześlij index.html, style.css i folder img.
  4. Zatwierdź zmiany przyciskiem Commit changes.

Krok 4 – Włącz GitHub Pages

  1. Otwórz zakładkę Settings.
  2. W menu bocznym wybierz Pages.
  3. W sekcji Build and deployment wybierz Deploy from a branch.
  4. Wybierz gałąź main.
  5. Wybierz katalog /(root).
  6. Zapisz ustawienia.

Krok 5 – Otwórz opublikowaną stronę

Po zakończeniu publikacji GitHub Pages udostępni adres witryny. 

https://nazwa-uzytkownika.github.io/moja-witryna/

Publikacja może potrwać kilka minut. Adres strony można sprawdzić w ustawieniach Pages.

📌 Zapamiętaj

W repozytorium projektu plik index.html powinien znajdować się w katalogu wybranym jako źródło publikacji lub w jego odpowiedniej strukturze.

16. Aktualizowanie opublikowanej witryny

Opublikowana witryna może być później modyfikowana.

Aktualizacja na hostingu tradycyjnym

  1. Zmodyfikuj pliki na komputerze.
  2. Przetestuj zmiany lokalnie.
  3. Połącz się z serwerem przez SFTP lub FTPS.
  4. Prześlij zmodyfikowane pliki.
  5. W razie potrzeby zastąp starsze wersje.
  6. Sprawdź działanie publicznej strony.

Aktualizacja na GitHub Pages

  1. Otwórz repozytorium.
  2. Zmodyfikuj plik HTML lub CSS.
  3. Zatwierdź zmiany.
  4. Poczekaj na zakończenie publikacji.
  5. Odśwież publiczną stronę.

Dlaczego zmiany czasem nie są widoczne?

Przeglądarka może korzystać z wcześniej zapisanej wersji zasobu znajdującej się w pamięci podręcznej.

W takim przypadku można ponownie załadować stronę, sprawdzić ustawienia pamięci podręcznej lub poczekać na zakończenie wdrożenia.

17. Sprawdzanie witryny na serwerze WWW

Po opublikowaniu strony należy sprawdzić jej działanie pod publicznym adresem.

Lista kontrolna

Element Co sprawdzić?
Adres Czy publiczny adres otwiera stronę?
HTML Czy wyświetlana jest właściwa zawartość?
CSS Czy style zostały poprawnie wczytane?
Obrazy Czy wszystkie grafiki są widoczne?
Menu Czy odnośniki prowadzą do odpowiednich miejsc?
HTTPS Czy witryna otwiera się przez HTTPS bez błędów certyfikatu?
Telefon Czy strona poprawnie działa na małym ekranie?
Konsola Czy nie pojawiają się błędy wymagające poprawy?

Testowanie na telefonie

  1. Otwórz publiczny adres na telefonie.
  2. Sprawdź czytelność tekstu.
  3. Sprawdź menu.
  4. Sprawdź obrazy.
  5. Sprawdź, czy nie pojawia się zbędne przewijanie poziome.

18. Najczęstsze błędy podczas publikacji

Problem Możliwa przyczyna Rozwiązanie
Strona nie otwiera się. Nieprawidłowy adres lub nieukończona publikacja. Sprawdź adres i status wdrożenia.
Brak stylów CSS. Niepoprawna ścieżka do arkusza. Sprawdź href w elemencie link.
Nie widać obrazów. Nieprawidłowa nazwa pliku lub ścieżka. Sprawdź src i strukturę katalogów.
Błąd 404. Żądany zasób nie został znaleziony. Sprawdź lokalizację i nazwę pliku.
Wyświetla się starsza wersja. Pamięć podręczna lub niezakończone wdrożenie. Sprawdź status publikacji i odśwież zasoby.
PHP nie działa na GitHub Pages. Brak obsługi PHP po stronie serwera. Wybierz hosting obsługujący PHP.

Wielkość liter w nazwach plików

Na wielu serwerach nazwy plików rozróżniają małe i wielkie litery.

Dlatego: 

Logo.png

i: 

logo.png

mogą oznaczać dwa różne pliki.

⚠️ Ważne

Strona może działać lokalnie na Windows, a po publikacji mieć błędy związane z wielkością liter w nazwach plików.

19. Bezpieczeństwo publikowania witryny

Publikując stronę, należy pamiętać, że jej publiczne pliki mogą być dostępne dla innych użytkowników.

Podstawowe zasady

  • Nie umieszczaj haseł w plikach HTML i JavaScript.
  • Nie publikuj danych dostępowych do serwera.
  • Nie przesyłaj prywatnych dokumentów do publicznego repozytorium.
  • Stosuj bezpieczne metody przesyłania plików.
  • Sprawdzaj uprawnienia dostępu.
  • Aktualizuj wykorzystywane oprogramowanie.
  • Przechowuj kopię projektu.
  • Sprawdzaj zawartość przed publikacją.

Przykłady plików, których nie należy publikować

hasla.txt
dane-uczniow.xlsx
kopia-bazy.sql
prywatne-notatki.docx

Publiczne repozytorium nie jest odpowiednim miejscem do przechowywania poufnych informacji.

20. Hosting tradycyjny a GitHub Pages

Cecha Hosting tradycyjny GitHub Pages
HTML i CSS Tak. Tak.
JavaScript w przeglądarce Tak. Tak.
PHP Na planach obsługujących PHP. Nie.
MySQL Na planach obsługujących bazy danych. Nie.
SFTP / FTPS Często dostępne. Nie jest metodą publikacji.
Publikacja przez repozytorium Zależnie od dostawcy i konfiguracji. Tak.
Własna domena Zwykle możliwa. Możliwa po konfiguracji.
Typowe zastosowanie Witryny statyczne i dynamiczne. Witryny statyczne.

📌 Wniosek

Do nauki publikowania prostych stron HTML i CSS GitHub Pages jest wygodnym rozwiązaniem.

Do projektów PHP i MySQL potrzebny jest hosting obsługujący te technologie lub odpowiednio skonfigurowany serwer.

  • Nie wolno publikować haseł i prywatnych danych.
  • Gotową stronę należy przetestować pod publicznym adresem.

Do publikacji potrzebne jest konto GitHub oraz możliwość utworzenia publicznego repozytorium.

Zadanie 1 – Przygotowanie witryny do publikacji

  1. Otwórz folder swojej witryny.
  2. Sprawdź, czy znajduje się w nim plik index.html.

  4. Sprawdź ścieżki do obrazów.
  5. Usuń niepotrzebne pliki robocze.
  6. Otwórz stronę lokalnie i sprawdź jej działanie.

Zadanie 2 – Hosting, domeny i DNS

W pliku raport.txt odpowiedz na pytania:

  1. Czym różni się hosting od domeny?
  2. Do czego służy system DNS?
  3. Czym różni się HTTP od HTTPS?
  4. Dlaczego do przesyłania plików lepiej używać SFTP lub FTPS niż zwykłego FTP?
  5. Dlaczego GitHub Pages nie uruchomi skryptu PHP?

Zadanie 3 – Utworzenie repozytorium GitHub

  1. Zaloguj się na GitHub.
  2. Utwórz nowe repozytorium.

  7. Zatwierdź zmiany.

  6. Poczekaj na zakończenie publikacji.
